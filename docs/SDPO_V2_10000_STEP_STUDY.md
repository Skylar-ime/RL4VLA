# Qwen2.5-VL-3B 辅助 SDPO：1 万步对照实验

## 研究问题与范围

任务为 `PutOnPlateInScene25Main-v3`。两组训练均从同一 `gen-robot/openvla-7b-rlvla-warmup` revision `735fd5d1f4472c4c9f3f998f0e89aa641af5ad03` 初始化，使用 seed 0、相同训练物体集合、并行环境数、采样温度、80 步 episode 上限和 10,000 个**环境动作步**。实验组为 `multimodal-correction-v2` SDPO，外部反馈模型 `Qwen/Qwen2.5-VL-3B-Instruct`；对照组为仓库现有 PPO，不调用外部模型。冻结 warm-up 仅评测。1 个 seed 只能描述本次运行，不能证明跨 seed 稳定性。

研究两个问题：学生在评测时只读取执行前图像和任务指令，随 SDPO 训练是否改善任务成功、抓持与搬运；在相同环境动作步数和相同训练墙钟时间下，SDPO 与 PPO 谁更快达到更高任务成功率。墙钟时间包括环境交互、反馈请求与重试、前后向计算、参数更新；中途评测耗时另列。PPO 和 SDPO 的优化器步数、算法目标不同，需同步记录，不能把同环境步数解释为同更新预算。

## 训练与评测协议

目标 checkpoint 为累计 0、480、2400、5000、10000 环境动作步。每个目标必须由实际执行和优化完成的动作计数确认；现有训练循环按 `num_envs × episode_len` 整批向下取整，不得把 4960/9920 冒称 5000/10000。保持 80 步 episode 上限，须实现边界处的部分 rollout 或精确中途保存，并验证 PPO 与 SDPO 都没有漏掉或多做参数更新。训练 seed 固定为 0；评测使用固定且逐集可追溯的 episode ID、物体和初始化状态。

固定验证集为 60 个 `test` episode，所有 5 个 checkpoint 均在同一批 episode 上评测；0 步 warm-up 共用结果。独立最终测试集为另外 100 个未参与中途评测或 prompt 调整的 episode，比较 warm-up 与两组 10000 步学生。每集最多 80 步，评测只加载学生，不调用教师或外部模型。验证集总计 540 集（共同基线 60 集、两组后续各 4×60 集），最终集 300 集，合计 840 集；实际环境动作步和 wall time 单独计量。

主要指标为逐集完整任务成功率。分阶段记录新建立抓持率、首次抓持步数、持续抓持率、掉落与提前释放、已抓持后送达目标的比例、物体到盘子的距离变化。另记录有效反馈数、格式拒绝/重试数、护栏逐字段修正数、教师条件分布变化、每 1000 环境步训练耗时、H800 和 4090 的利用率/显存。抓持或方向投影只是诊断，不替代任务成功率。结果按相同环境动作步数和相同累计训练墙钟时间绘图，并报告到达预先固定成功率阈值的时间及曲线面积；未达到则如实报告。若评测集仅更换 episode 而仍来自相同 `test` 物体集合，不宣称未见物体泛化。

## 资源与执行

robot 仓库 `/public/home/s2250018/project/RL4VLA` 与本机使用同一 `ex/v2` Git 修订；正式训练只申请 **1 张 H800**。本机 **1 张 RTX 4090** 托管 Qwen2.5-VL-3B-Instruct 反馈服务，仅绑定本机私网地址并使用随机 Bearer key 供 H800 作业调用；计算节点到该地址的连通性已用 GPU-free Slurm 作业验证。训练入口为 `SimplerEnv/scripts/run_sdpo_v2_10000_h800.sbatch`，默认 `NUM_ENVS=8`、`BUFFER_INFERBATCH=8`，提高 H800 rollout 与 OpenVLA 前向批量；外部反馈仍逐决策更新。先串行跑 SDPO，再在相同 H800 资源配置下跑 PPO；两组不能同时争抢 H800。以端到端环境动作步/小时、反馈延迟、优化器步数、GPU 占用和 OOM 为依据调节并行环境数。逐反馈更新的依赖会让 H800 在等待本地 Qwen 时空闲；测量这部分空闲，不以虚假的 100% 利用率作为目标。保持最多两张 GPU 同时占用。

本机固定评测入口为 `SimplerEnv/scripts/run_sdpo_v2_10000_eval.sh`。验证集传 `EVAL_EPISODE_START=0 EVAL_EPISODES=60`，最终测试集传 `EVAL_EPISODE_START=60 EVAL_EPISODES=100 EVAL_NUM_ENVS=5`；使用不同 episode ID，后者不得在中途评测或提示词调试时运行。每组每个 checkpoint 单独指定唯一 `EVAL_LABEL` 和 `VLA_LOAD_PATH`。训练关闭内置评测；累计训练墙钟和优化器步数写入 W&B 及 `environment_steps.json`，避免把固定评测时间算进训练速度。

启动前验证 3B 服务对两图请求可用、模型 ID 和 JSON 结构匹配，并完成少量真实步骤的机制检查；这属于训练启动检查，不是额外的反馈准入实验。反馈连续拒绝、模型服务不可达或产物不完整时停止并保留原件；不得静默回退到规则标签。每个阶段保留完整配置、Git 修订、模型来源、W&B run、原始反馈、图像哈希、更新次数、checkpoint 和逐集评测。W&B 云端不可用时先保存离线 run，实际同步和 API 可见后才标注已上传。完成 smoke 后删除临时脚本、密钥、重复权重和无关日志；保留有效审计与训练结果。
